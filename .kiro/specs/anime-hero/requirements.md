# 《我成了动漫主角》需求

## 背景
小红书小工具小游戏，AI 互动故事玩法（参考 OOC: The Playable Anime）。玩家扮演主角，剧情跟着玩家的行动走。

## 硬约束
- R1 零网络请求：不接在线 AI 接口，不加载网络图片、字体、脚本。用 CSP `connect-src 'none'` 兜底。
- R2 本地剧情引擎：自由输入 → 关键词意图识别 → 命中当前场景预写回应；识别不到走场景通用推进回应。没有死路，没有假按钮，没有“暂未开放”。
- R3 包体 < 10MB，游戏内标注“AI 制作”。
- R4 触控优先：统一 tap 处理（touchend + click 去重），不依赖 Pointer Events。

## 玩法
- R5 创建主角：名字 + 4 选 1 特质，特质影响数值。
- R6 至少 4 章，每章多个场景；每个场景 2~3 个选项 + 自由输入框。
- R7 意图分类 8 类：战斗、对话、探索、移动、道具、休息、逃跑、帮助；每类在每个场景都有接剧情的预写回应。
- R8 数值：声望、体力、绯月好感、雪乃好感；选项和自由行动都会改数值，数值影响后续选项和结局。
- R9 至少 3 个结局，由数值和关键选择决定，能实际打出来。

## 画面与声音
- R10 每个场景有程序化 SVG 场景图，学园/森林/小镇/遗迹/决战能分清；两位主角有 SVG 立绘；不用网络图片、不用 emoji 当画面。
- R11 WebAudio 合成音效，可静音。

## 存档
- R12 localStorage 保存进度、数值、已解锁章节；可重新开始；通关后可重玩冲其他结局。

## 框架（追加需求）
- R13 数据驱动：章节、场景、选项、意图回应、数值效果、结局全部写在内容数据里。加新章只加数据，不改引擎。
- R14 分层：引擎核心 / 内容层 / 表现层 / 商业化层（PaymentProvider 接口后面）。
- R15 可测试：种子随机、`render_game_to_text` 与 `advanceTime` 钩子、无头自测。

## 商业化（默认关闭）
- R16 经济：体力（推进消耗、时间恢复）、软货币学园币、硬货币宝石；每种货币至少 2 个来源 2 个去处。
- R17 付费点：章节通行证、番外解锁、结局图鉴、体力补充、宝石包；每个带 `price_rmb`（3/6/12）；走 PaymentProvider 桩；没有支付权限时不显示购买入口，不做假按钮；可用游戏内货币先行兑换。
- R18 留存：每日签到、结局收集进度奖励、章节完成奖励、每周上新节奏（章节带上线日期）。
- R19 改动说明写清闭环：获客（挂载笔记）→ 游玩 → 体力墙 → 通行证/付费解锁 → 完成章节 → 新章上线 → 回流再付费，含数字和理由。

## 交付
- R20 game.js、index.html、style.css（另有 content.js 内容数据）；自测脚本与结果；改动说明。
